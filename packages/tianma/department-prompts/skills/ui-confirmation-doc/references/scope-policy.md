# 截图范围口径（强制执行）

确认书的作用是**逐屏签字确认**，不是产品说明书。截图越多，客户越难逐条核对，页数也会失控。
默认口径：**一级页面全覆盖 + 核心二级页面抽样**。

## 一、一级页面（必须全部覆盖）

一级页面 = 用户能直接进入的顶层页面，不经过任何中间跳转。

| 端 | 一级页面判定 | 覆盖要求 |
|---|---|---|
| Web 管理后台 | 登录页 + 侧边栏一级菜单的每一项（路由表里挂在布局下的直接子路由） | 一页不漏，一项一张 |
| 微信小程序 | tabBar 五个页面 + 主包里的独立入口页（搜索、商品列表、登录） | 一页不漏，一项一张 |

一级页面的数量由路由表 / `app.json` 决定，**以代码为准，不凭印象**：

- Web：读 `src/router/index.ts`（或等价路由文件），取布局组件的 children；
- 小程序：读 `app.json` 的 `pages` 与 `tabBar.list`。

## 二、二级页面（只取核心业务链路，5 张以内/端）

二级页面 = 需要参数、需要从列表/详情跳转才能进入的页面与弹窗。
**只挑能体现业务闭环的那几张**，按下列优先级取，取够即停：

| 优先级 | 小程序 | Web 后台 |
|---|---|---|
| 必取 | 商品详情、确认订单、订单详情（含物流） | 一个代表性新增/编辑弹窗 |
| 必取 | 会员卡详情或核销（有会员/核销业务时） | 一个审核或详情弹窗（发货/退款/提现之一） |
| 选 1 张 | 购物车、分销中心 二选一 | 权限或角色视角（有多角色时） |

## 三、明确不截（除非用户点名要）

1. 列表页的每个弹窗都截（只留一个代表）；
2. 同一页面的每个状态 tab（待支付/待发货/已发货…）、空态、错误态；
3. 辅助页：地址新增/编辑、我的收藏、消息中心、在线客服、关于我们、设置；
4. 结构重复的页面：同版式的多个详情页只留一个；
5. 二次确认框单独成图（合并进对应操作图即可）。

## 四、数量红线

- Web 后台：8–12 张
- 小程序：8–12 张
- 合计：16–24 张（对标模板样例的 27 张）

超过 30 张说明没做取舍，先删：状态 tab → 辅助页 → 重复结构页 → 二级弹窗。

## 五、命名与图注

- 文件名：`序号-英文短名.png`，序号与图号一致，两位数字（`01-login.png`）。
- 图注：`图 NN　中文页面名（/实际路由）`，编号全文连续，不按端重新计数。
  小程序路由写成 `/pages/home/index`，Web 写成 `/dashboard`，带参数的写 `/packageA/pages/detail/index?id=` 这类可读形式即可。
