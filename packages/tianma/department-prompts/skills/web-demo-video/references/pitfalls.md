# 踩坑清单（通用化）

每条都注明：**现象 → 根因 → 本技能的处理**。
带 🛡 的条目是本技能已内建防护的，不要绕过；带 ⚠️ 的需要在写 plan 时注意。

---

## 一、浏览器与协议层

### P1 🛡 可见性判断不能用 `offsetParent`
- **现象**：弹窗、抽屉、Toast 全部「找不到」，涉及弹窗的步骤成片缺失。
- **根因**：`position: fixed` 元素的 `offsetParent` 恒为 `null`，被误判为不可见。
- **处理**：统一用「`getBoundingClientRect` 尺寸 > 0 + `display/visibility/opacity`」判断。

### P2 🛡 输入框必须用原生 value setter + 派发事件
- **现象**：账号密码填了，登录却失败或表单校验不通过。
- **根因**：直接 `input.value = x` 不触发框架的受控更新（Vue 的 v-model / React 的 onChange）。
- **处理**：取原型链上的 `value` setter 赋值，再派发 `input`、`change`，最后 `blur` 触发校验。

### P3 ⚠️ 不做整页导航
- **现象**：登录成功后一跳转就退回登录页。
- **根因**：很多 SPA 把令牌只存内存，整页导航等于刷新，登录态丢失。
- **处理**：只用 `nav`/`click` 走应用内路由；`probe` 的 `rawPaths` 仅在确认应用允许整页跳转时使用。

### P4 🛡 调试端口不要写死
- **现象**：多任务/CI 上偶发连不上浏览器。
- **根因**：固定端口被占；或上一轮进程没退干净。
- **处理**：`--remote-debugging-port=0` 由系统分配，从 `<user-data-dir>/DevToolsActivePort` 读实际端口；
  启动前清理残留的 `DevToolsActivePort` / `SingletonLock`。

### P5 🛡 浏览器子进程不要用管道 stdio
- **现象**：受限沙箱下直接 `EPERM`。
- **根因**：沙箱禁止打开命名管道，`child_process` 默认的 `stdio: 'pipe'` 会失败。
- **处理**：`stdio: ['ignore','ignore','ignore']`；需要日志时把 stderr 重定向到**文件**（fd）。

### P6 🛡 `--headless=new` 在旧内核不存在
- **处理**：启动失败自动依次退化 `--headless(legacy)`、再加 `--no-sandbox --disable-dev-shm-usage`。

## 二、抓帧与时间轴（最容易整段失败的环节）

### P7 🛡 单次抓帧必须给硬超时
- **现象**：录了 107.8 秒，成片只有 79.3 秒，中间 35 秒整段没有画面。
- **根因**：一次 `Page.captureScreenshot` 无限挂起，抓帧循环被阻塞 30 秒；期间演示脚本继续走完，
  等超时返回时录制已结束 → 那 30 秒的内容压根没被采到。
- **处理**：每次抓帧 4 秒硬超时，失败只计数不中断；频率降到 5fps。

### P8 🛡 时间轴不能按「帧间隔」拼
- **现象**：字幕与画面对不上、成片比录制短。
- **根因**：用相邻帧时间差当帧时长，会把抓帧空档压缩掉（空档 30 秒 = 视频少 30 秒）。
- **处理**：按演示真实时长 @25fps **均匀重采样**，每个输出帧取「不晚于该时刻的最近一帧」。
  这样总时长恒等于演示时长，空档只表现为画面静止，并统计 `heldSlots`/`maxGapSec` 作为质量门禁。

### P9 🛡 concat 清单的收尾语法
- **现象**：末帧丢失或时长异常。
- **根因**：ffmpeg concat 要求每个 `file` 后跟 `duration`，且**结尾必须再补一行 `file`**。
- **处理**：按此规则生成，见 `lib/capture.mjs#buildTimeline`。

### P10 ⚠️ 抓帧频率与体积
- 5fps 对以点击交互为主的演示足够；1600×900 JPEG 约 120–200KB/帧，60 秒约 60MB。
- 需要流畅动画时才提高 fps，并同步关注磁盘与编码耗时。

## 三、交互定位层

### P11 🛡 带角标的导航项精确匹配会失败
- **现象**：点侧边栏「入驻审核」报 `NO-TEXT`，但可用清单里明明有它。
- **根因**：该元素的 `innerText` 是 `入驻审核\n1`（含未读角标），精确相等判断不成立。
- **处理**：先精确匹配，失败后退化为「归一化空白后的前缀匹配」，并取最短命中（避免点到大容器）。

### P12 🛡 下拉不能按 placeholder 找
- **根因**：Element Plus / Ant Design 把占位渲染成 `<span>`，`.el-select input` 没有 placeholder 属性。
- **处理**：按下拉**容器的可见文本**定位，展开后只从**可见的**选项里按文本匹配（同页常存在多个 dropdown）。

### P13 🛡 详情页表单没有 placeholder
- **处理**：`fill` 支持 `by: "label"`，按表单项 label 文本定位到其内部输入框。

### P14 🛡 二次确认按钮文案因场景而异
- **现象**：`confirm()` 点不动。
- **根因**：同一组件库的确认键在不同场景是「重置密码」「通过并上线」「批量通过」……
- **处理**：`confirm` 必须传 `buttonText`；失败时回吐当前所有按钮文案。

### P15 ⚠️ 行号索引在列表刷新后失效
- 任何筛选/排序/翻页后，`.el-table__row` 的下标含义都变了。
- **处理**：步骤里在列表变化后重新按可见状态操作；如需跨筛选稳定定位，优先用「行内按钮文本 + 断言」组合，
  或让被测应用给行加上稳定的 `data-*` 标识。

### P16 🛡 Toast 是 fixed 且会自动消失
- 读取时机太晚就为空。**处理**：动作后立即读；统一走修好的可见性判断。
- 更稳的写法是**用 `waitText` 轮询代替「固定 `wait` + `assert toast()`」**：
  `{ "type": "waitText", "text": "营地信息已保存", "timeoutMs": 9000 }`。
  固定等待的窗口取决于「接口延迟 + Toast 停留时长（默认 3s）」，一旦接口比预期慢一点就偶发失败；
  轮询只要在超时内出现过就算通过，实测把这类偶发失败直接消灭。

### P17 ⚠️ 断言的写法受限
- 只允许只读探针：`rows()`、`hasText()`、`path()`、`toast()`、`overlayTitle()`、`downloadCount()`。
- 禁止任意 JS（`eval`/函数/属性访问链）。需要逃生门时用 `{"type":"eval"}` 并显式开 `allowEval`。
- `assert` 支持可选 `timeoutMs`：给了就在超时内反复求值（每 200ms），用来等「会自动消失的瞬时状态」。
  例：`{ "type": "assert", "expr": "toast().includes('已保存')", "timeoutMs": 9000 }`。
  不给则只求值一次（向后兼容）。
- 历史坑（已修，留档备查）：`rows()` 曾未过滤可见性，把 el-date-picker 关闭后仍留在 DOM 里的
  日历表算成数据行（用户列表 6 行被数成 18 行）；`downloadCount()` 曾恒为 0，因为没有任何代码写入
  `window.__demoDownloads`。现在 `rows()` 只数可见数据行（索引与计数同源，`rowAction`/`checkRow` 一致），
  `downloadCount()` 由录制期的下载目录轮询供给。

## 四、字幕与配音

### P18 🛡 ASS 的 alpha 是反的
- **现象**：白字压在表格上，描边几乎看不见，可读性差。
- **根因**：`&HAABBGGRR` 里 `AA` 是透明度，`0x00` 才是全不透明；写成 `0xC0` 等于 75% 透明。
- **处理**：`OutlineColour=&H00000000` + `Outline=3`。

### P19 🛡 中文字体缺失会渲染成方块
- **处理**：启动探测 CJK 字体并按平台选名（Microsoft YaHei / PingFang SC / Noto Sans CJK SC）；
  缺失时警告并允许 `--font-name` 覆盖。

### P20 🛡 文本不要走 argv
- **根因**：Windows 下把非 ASCII 文案当命令行参数传给原生 exe 极易乱码。
- **处理**：文案写入 UTF-8 文件，引擎读文件。

### P21 🛡 开启播报时，时间轴由配音长度驱动，而不是反过来
- **现象**：语音还在念，画面已经跳到下一步。
- **处理**：先合成配音、量出时长，再令每步停留 = `max(minSec, 配音时长 + 0.9s)`。

### P22 🛡 默认不出配音；没有 TTS 就降级，不要失败
- **默认**：`narration` 默认 `false`，成片只烧字幕，节奏由 `minSec` 决定（多数场景不需要语音）。
- **开启后**：无可用语音引擎时只烧字幕，成片依然可交付，并在报告里标注降级项。

### P22b 🛡 无声版最容易翻的车：`minSec` 给太短
- **现象**：字幕一闪而过，观众来不及读；视频看起来「很快、很碎」。
- **根因**：没有配音兜底时，`minSec` 是步长的唯一来源，而人们常按「动作需要多久」而不是「字幕要读多久」来给。
- **处理**：`minSec ≈ 中文字数 ÷ 6`，下限 3.5s；24–29 字的一句话给 4.5–5s。改完先干跑，看每步耗时是否被拉长。

## 五、合成与交付

### P23 🛡 `-shortest` 会把视频截短
- **现象**：成片时长比时间轴短约 0.9 秒（恒定偏移，容易误判成「抓帧丢了」）。
- **根因**：音轨总长通常短于画面（最后一句配音结束后还有画面停留），`-shortest` 以较短者为准。
- **处理**：合流时对音轨加 `-af apad` 补静音，再 `-shortest`，两者长度对齐。

### P24 🛡 中文文件名不要交给原生 exe
- **处理**：先输出 ASCII 名，再用 Node `renameSync` 改成目标中文名。

### P24b 🛡 交给原生 exe 的路径必须绝对化（`--workdir` 传相对路径会炸）
- **现象**：浏览器启动失败，报「未产出 DevToolsActivePort」，`browser.log` 里只有 extension sync 之类的噪声；
  事后看 `<workDir>/browser-profile` 是**空的**（0 个条目）——这是本坑的指纹。
- **根因**：`--workdir work` 这类相对路径会被拼进 `--user-data-dir` 交给 Edge/Chrome，浏览器把它解析到别处，
  于是 `--user-data-dir` 等于没生效（去加载默认 profile），调试端口文件自然不落在我们期望的目录。
- **处理**：`workDirOf()` 里统一 `resolve()` 成绝对路径（已内建）。教训适用于所有传给原生 exe 的路径。

### P24c 🛡 结束浏览器要连子进程一起杀
- **根因**：Windows 上 Edge/Chrome 是「启动器 + 真正的浏览器进程」两段式，启动器很快退出；
  只 `proc.kill()` 启动器会留下占着 profile 锁的孤儿浏览器进程，**下一次运行必然启动失败**。
- **处理**：Windows 上用 `taskkill /PID <pid> /T /F` 杀整棵树（已内建）；另外重试时每轮换一个
  profile 目录（`browser-profile-r1`/`-r2`），避免残留锁把三次重试一起带死。
- **附带**：启动器「退出」不等于启动失败——端口文件可能在它退出之后才写出，所以退出后再给 5s 宽限期
  （`EXIT_GRACE_MS`），别一退出就判死。

### P25 🛡 `Start-Process` 唤不起 AppX/Store 默认应用
- **现象**：脚本报「已打开」，实际什么都没弹（静默失败）。
- **处理**：统一交给系统 shell：`explorer.exe`（Win）/`open`（mac）/`xdg-open`（Linux）。

### P26 🛡 部分 ffmpeg 构建不支持 `-filter_script:v`
- **现象**：`Unrecognized option 'filter_script:v'`。
- **处理**：滤镜以单个参数用 `-vf` 传入；在 Windows 上尤其不要拼 shell 引号。

### P27 🛡 音轨要自检电平
- **处理**：`volumedetect` 取 `mean_volume`/`max_volume`；`max < -60dB` 视为静音，写进报告。

## 六、工程与环境

### P28 🛡 编辑文件可能搞崩 dev server
- **现象**：录制中途站点不可达，日志显示 Vite 因 `EBUSY` 退出。
- **根因**：某些编辑器的原子写入会在源码目录建 `.xxx.ts.<pid>.<guid>.tmpdir/`，被文件监听撞上。
- **处理**：录制前做站点可达性预检；失败时明确提示重启 dev server 后重录。

### P29 🛡 单字/连写的命令行参数
- **现象**：`--workdir` 传了没生效。
- **根因**：参数归一化只处理了 kebab-case，`workdir` 与 `workDir` 两套写法各错一半。
- **处理**：显式 alias 表（`workdir→workDir`、`dryrun→dryRun`…）。

### P30 ⚠️ 一键成片前先确认被测环境
- 演示会产生真实副作用（保存、导出、停用）。**优先指向 mock/测试环境**；
  对生产环境取样时开 `readOnly: true`（拒绝点含「保存/提交/删除/停用/启用/重置」语义的按钮）。

## 七、方法论（不是技术坑，但更值钱）

### P31 「打开页面 + 讲解」不是演示
第一版做成逐页打开配讲解，被评为「效果很差」。正确做法：**每步都有真实操作**（点击、筛选、
填表、勾选、导出、打开弹窗），讲解压到一句话。

### P32 先侦察再写脚本
靠猜按钮文案会反复试错。`probe` 一次跑完所有目标页面回吐可点清单，直接照抄真实文案。

### P33 干跑优于重录
调脚本阶段不要反复正式录制。`--dry-run` 走同一套步骤但不抓帧，迭代成本降到 1/3。

### P34 交互必须带可核对的副作用
每步都要有 Toast 文案或落盘文件能对上，否则「以为点上了」会一路带到成片里。

### P35 真的点一遍能发现静态检查发现不了的缺陷
本技能在真实项目上借此发现两个缺陷：后台的车位池重复计数（口径错了导致状态显示错误）、
以及表单保存永远失败（校验正则否掉了自己的种子数据）。
**类型检查、构建、静态自检都发现不了这两类问题。**
