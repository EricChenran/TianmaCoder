### 开发过程中修掉的五个坑

1. **`HashSet[string]` 里塞 hashtable**
   补齐依赖那一步用 `HashSet[string]` 装 `@{d=...; r=...}`，hashtable 被强转成字符串，
   集合里只剩一条垃圾数据 → 补齐步骤一个文件都没下（16713 因此少了 98 个文件，
   包括整套 Font Awesome 字体）。改用 `List[object]` + `pscustomobject`。

2. **水印正则按中文文案匹配**
   最初匹配 `演示代码`，但各年代注入文案完全不同（`这是演示代码` / `当前为演示代码` /
   `此代码已混淆`），8047 漏清 60 处。改用 `bootstrapmb.com` 域名做锚点。
   顺带发现 host 自检串也在变（`ot` / `ap` / `stra`），但它们都是 `bootstrapmb` 的子串。

3. **按 UTF-8 写回 GBK 文件**
   8047 的 CSS/JS 是 GBK。若按 UTF-8 读改写回，中文注释全部变乱码。
   加入编码嗅探（UTF-8 BOM → 严格 UTF-8 → GBK/CP936）并按原编码写回。

4. **完整性校验只认「相对引用所在目录」一种路径**
   模板作者常把 `url(assets/img/x.png)` 写进子目录的 CSS，导致 5 处真实存在的图片
   被误报为缺失、且补不下来。改为同时尝试「相对引用目录」和「相对站点根」两种候选。

5. **短路径导致归属判断全灭（最隐蔽的一个）**
   用 `$fullLocal.StartsWith($dest)` 判断文件是否落在输出目录内。当 `-OutRoot` 位于
   8.3 短路径下（如默认常见的 `%TEMP%` = `C:\Users\ADMINI~1\...`）时，
   `Get-ChildItem` 返回的却是长路径 `C:\Users\Administrator\...`，
   `StartsWith` 恒为 false → **整个「补齐依赖」步骤静默跳过，不报任何错**。
   在 D 盘路径下测试完全正常，换到 `%TEMP%` 才暴露。
   修法：建目录后立即用 `(Get-Item -LiteralPath $dest).FullName` 规范成长路径，
   并把归属判断换成 `Test-PathUnder`（忽略大小写 + 带分隔符边界）。
   顺带修了 `-CodeOnly` 未约束第 5 步的问题（现在同样只补代码类依赖）。
