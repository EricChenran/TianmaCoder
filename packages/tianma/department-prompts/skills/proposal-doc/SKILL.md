# 实施方案（proposal-doc）— 宜春市天码信息有限公司

本技能只出一种文档：**实施方案**。没有第二种分支，也没有可切换的类型参数。

## 定位

给客户看的建设文档：讲清**建什么、怎么建**。只写需求与技术，不写商务程序性内容。

**触发**：用户要求整理需求、出实施方案、建设方案或技术方案时使用；产出一律是实施方案，不另做投标文件或技术方案。

## 执行流程

1. **收集资料**：按 `references/intake-checklist.md` 的三问一次问全，不要挤牙膏。
2. **判定缺料**：能向用户要到的先要；要不到且用户让"先做"，进入降级模式（见下）。
3. **写 `content.py`**：复制 `scripts/content_template_impl.py`，填 `META`、`CONTENT`、`NUMBERS`。
4. **画图**：图片放 `<项目目录>/img/`；通用图元用 `scripts/diagrams.py`（`vflow/hflow/layers`），原型界面用 `scripts/ui.py`，复杂分支用 `scripts/dkit.py`。**不画甘特图、不标周次**。
5. **生成**：

   ```bash
   python <技能目录>/scripts/docbuild.py "<项目目录>/content.py" -o "<项目目录>"
   ```

   输出文件名默认取 `META["doc_name"]`，即 `<系统名>实施方案.docx`，不要另起名字。
6. **转 PDF**：用 LibreOffice Kit 的 `convert`（或本机 Word 另存），生成同名 `.pdf`。
7. **逐页目检**：封面、目录页码、表格、图与图题、页码奇偶、空白页。
8. **汇报**：两三句话说明章节、数据来源、缺料删除了什么；用 `present` 交付 docx 与 pdf。

## META 与固定输出

`META` 只有四个键，多一个都不要写：

| 键 | 值 |
|---|---|
| `title` | 系统名。客户给的名字照用；没给就按"业务对象 + 平台/系统/小程序/APP"起名 |
| `subtitle` | 固定 `"实 施 方 案"` |
| `doc_name` | 固定 `<系统名>实施方案`，用于页眉与默认文件名 |
| `org` | 编制单位，默认 **宜春市天码信息有限公司** |

- 封面不写项目编号与委托单位：`project_no`、`client` 缺省为空字符串，脚本跳过空行。
- 交付物只有两件：`<系统名>实施方案.docx` 与同名 `.pdf`。

## 七章骨架（固定，不得增删章）

```
第一章　项目概述与需求理解    背景 → 需求复述 → 总体工作流程（图）
第二章　总体技术方案          设计原则 → 总体架构（图）→ 技术选型（表）→ 数据与状态
第三章　功能模块技术方案      按业务分区分组（如 商品管理、订单管理、会员管理），不按技术分层命名
第四章　业务流程设计          每条链路一张流程图，主链路与分支链路都要成条
第五章　系统演示              原型截图按业务分组，图注写"示意"；没有真实截图就不放
第六章　结论                  3 段以内：可行性 → 选型可替换性 → 扩展性
第七章　附件与交付清单        只列本项目真实存在的交付物与文件
```

- 章序号用中文数字，章标题与序号之间用全角空格；每章另起页。
- 一级标题"一、"、二级"（一）"、三级"1."，不跳级。
- 图表编号全文连续：图1…图N、表1…表N，正文先引后出（"见图3""见表2"）。
- 一个功能模块的标准写法：`（一）小标题。` → 建设内容 → 技术要点（给可核对的数字，且进台账）。

## 六类禁令（一律不出现）

1. 投标函、投标承诺、法定代表人签字、盖章页；
2. 工期天数、工作日数、里程碑日期、周次刻度（含图里的"第 N 周"标签）；
3. 质保期、响应时限、解决时限、可用性等 SLA 指标；
4. 报价、分项金额、开标一览表、投标有效期；
5. 招标人、招标编号、评标办法、评分分值等招标程序表述；
6. 资质等级、业绩合同金额、人员证书编号、财务数据。

另：不写收费模式、定价策略、招商打法、试点推广节奏、人员编制调整这类运营建议。

## 缺料降级模式

资料缺失且无法从用户材料中取得时：

1. **先一次性问全**，不要复用上一轮假设，不要来回挤牙膏。
2. 用户取消提问或表示"先做"时，**默认进入降级模式**：删掉该章节、该表格、该数字表述。**不得**改写成定性描述，也不得用经验值顶上。
3. 交付说明中单列**"因缺料删除的内容"**：删了什么、缺哪项输入。没有删除项就写"无"。
4. 优先级固定：**不编造 ＞ 结构完整 ＞ 篇幅**。

## 封面

- 纵向居中：项目名称（二号宋体加粗）→ 副标题"实 施 方 案"（三号楷体）→ 编制单位与编制日期（三号仿宋）。
- 编号与委托单位留空，封面不渲染空行；**不得出现【】占位**，交付前逐字检查。
- 日期由脚本取系统当天，写成"二〇二六年十一月二日"这种中文格式。

## 数字台账 NUMBERS

`content.py` 顶部维护 `NUMBERS` 字典：

```python
NUMBERS = {
    "60 秒": "需求材料 3.2 节",
    "50%": "用户确认",
    "20 字": "原型稿 第 4 页",
}
```

- 键：正文里**数字的原样字符串**（含单位与空格，如 `"60 秒"`、`"50%"`、`"20 字"`）；图表编号（图3、表2）与交叉引用不算。
- 值：出处 = 素材文件名 + 位置，或"用户确认"。
- `docbuild.py` 构建前扫描 `CONTENT` 全文：有数字但没台账，或台账缺项，直接打印缺失项并 `exit(1)`，不生成文件。
- 全文没有数字是合法的（`NUMBERS` 可留空）；有数字但无台账是非法的。

## 版式与三个固化点

版式规范见 `references/format-spec.md`（A4、版心 156×225mm、仿宋三号、固定行距 28.8 磅、三线表、页码"— 1 —"、页眉 LOGO、水印），已全部固化在 `scripts/docbuild.py`，**不要手工改版式**。

以下三处实现细节不要回退：

1. **目录→正文用 `WD_SECTION.CONTINUOUS` 分节**，首个章标题自带 `page_break`；否则目录排满两页时会多出一张空白页。
2. **表头单元格设 `keep_with_next`**，否则表题与表头留在页底、数据行被推到下一页。
3. **`build_cover` 遇到空值跳过该行**，`apply_meta` 对 `project_no` / `client` 支持显式置空（不能写成 `or` 默认值）。

## 常见坑

- 表格 `widths` 合计必须 = 156（mm），否则溢出；细则见 `references/content-blocks.md`。
- 图宽默认 154mm，原型图 150mm；单图高度控制在 120mm 内，留白要够。
- 段落"不缩进"必须显式写 `w:firstLineChars="0"`，只写 `firstLine=0` 会被样式覆盖。
- 图片段落行距必须单倍，否则固定行距 28.8 磅会把图裁掉。
- 目录页码用 `PAGEREF` 域，不要用 `TOC` 域（LibreOffice 渲染会变灰底）。
