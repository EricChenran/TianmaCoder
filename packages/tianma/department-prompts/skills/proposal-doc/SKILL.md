# 方案书与投标文件（proposal-doc）— 宜春市天码信息有限公司

一套排版引擎，两种工作模式。**先判断模式，再动手。**

## 选模式

| 模式 | 触发说法 | 输入 | 产出 | 章节结构 |
|---|---|---|---|---|
| **方案模式**（默认） | "写个方案""技术方案""建设方案""把需求整理成方案" | 客户需求材料 + 案例目录 | 技术方案 DOCX + PDF | 六章 + 附件 |
| **招投标专员模式** | 给了招标文件，或说"投标""响应文件""标书" | 招标文件 + 资质材料 + 案例目录 + 投标报价 | 投标文件 DOCX + PDF + 应答核对表 + 废标风险清单 | 完全按招标文件规定 |

判断不清时问一句："这次是出技术方案，还是要照着招标文件编投标文件？"

两个模式的差别只有三处：**结构由谁定**（我们定 vs 招标文件定）、**报价写不写**（默认不写 vs 必须写）、**要不要废标自查**（不用 vs 必须有）。

## 铁律（两个模式通用）

1. **资料缺失或不确定，必须先问用户**，一次把问题问全，不得自行编造。清单见 `references/intake-checklist.md`。
2. **案例、客户名称、金额、成效数据** 四类内容，没有用户的真实材料就**不许写具体数字**。可以写占位（`【待案例库检索】`），但必须在交付说明里逐条列出来。
3. **原型图、截图、演示视频** 若用户没提供，本文档里画的是"示意稿"，正文与汇报里都要说清楚，不能冒充真实系统截图或已拍好的视频。
4. 版式不许手改。页面、字体、行距、表格、页码、目录全部由 `scripts/docbuild.py` 固化实现，改版式就改脚本，别在文档里东补西补。
5. 数字口径要自洽：正文、表格、报价里的同一个数，全文只能有一个值。
6. **只写需求与技术，不写运营建议**。收费模式、定价策略、招商打法、试点推广节奏、人员编制调整这类内容一律不写；客户的经营目标只在"需求复述"里如实转述一句。图里也不许出现"招商""服务费调整"这类字样——图注和图内文字同样受约束。
7. **投标模式下，招标文件的格式要求高于本技能的版式规范**。两者冲突时按招标文件，并在交付说明里写明改了哪些地方。
8. **★（不满足即废标）条款必须逐条确认**。无法满足的当场告诉用户，不许"先写着、后面再补"。

## 招投标专员模式

七步走完再动手写正文，细则与红线清单见 `references/bid-playbook.md`。

1. **通读招标文件**，抽出五张清单：资格条件、评分办法、技术需求（标出 ★ 与 ▲）、格式与装订要求、废标条款。逐条编号，形成"招标要求清单"。
2. **拆评分**。把评分表拆成"得分项 → 我方证据 → 落在第几页"，把技术分与商务分分开统计，算出理论上限并标出拿不稳的分——这几项决定后面正文的详略。
3. **定目录**。完全照招标文件的章节顺序与标题原文，不自创、不合并。招标文件没规定的部分，才套方案模式的六章骨架。
4. **逐条响应**。技术响应表与商务偏离表都用四列：`条款号 → 招标要求原文 → 我方响应 → 证明材料页码`。★条款必须"完全响应"，▲条款逐条应答，其余条目可合并但不得漏项。
5. **取证据**。资质、业绩、人员、财务数据只从用户给的目录里取；取不到的列进"待补清单"，不许用相近项目顶替。
6. **出稿**。复用 `scripts/docbuild.py`，内容骨架用 `scripts/content_template_bid.py`；长表的分页与表头重复见 `references/content-blocks.md`。
7. **废标自查**。对照红线清单逐项打勾，产出两份东西：**应答核对表**（哪条要求在哪一页）和**废标风险清单**（有风险项 + 建议处置）。

投标模式特有的三条：

- **报价必须写**：开标一览表是废标项，金额、大写、税率、有效期缺一不可。
- **不虚构**：资质等级、业绩数量、人员证书、财务数据一律以材料为准；材料没有就写"待补"，并在核对表里标红。
- **格式从招标文件**：封面是否要写项目编号、是否要法定代表人签字页、是否双面打印、份数与密封方式，全按招标文件，本技能只负责排版与出 PDF。

## 方案模式：五步流程

## 第一步：收集资料（缺就上门问，别猜）

按下表逐项核对，**任一为"没有/不确定"就停下来问用户**。问的时候一次列全，不要来回挤牙膏。

| 组 | 必须确认的事 | 没有时的处置 |
|---|---|---|
| A 商务 | 项目名称、副标题（技术方案／建设方案） | 名称可由你拟 2 个候选请用户选。**项目编号、委托单位默认不写**——封面只留编制单位与日期，用户明确要求才加 |
| B 需求 | 客户原话、现状痛点、规模数据（面积/点位/并发/用户数）、三条主线目标 | 必须问；规模数据是后面所有测算的地基 |
| C 技术 | 是否已有既定技术栈或指定供应商、需对接的既有系统、部署与合规要求（本地/云/等保） | 可以按行业常规给建议，但要标注"建议值，待确认" |
| D 案例 | **用户给一个本地目录**，目录里放案例材料（docx / pdf / 图片 / 表格都行） | 你不许编。按下方"案例目录匹配"处理；目录没给就写检索说明 + `【】` 空表，交付时提醒补 |
| E 视觉 | 是否已有原型图／截图／设计稿／演示视频 | 没有则本次现画示意稿，并在图注里写"示意" |
| F 报价 | 含税口径、是否含运维、分项单价或总价上限、付款节点 | **默认整节不写报价**（见第五章说明）。用户明确要才加；只给总价时按经验拆分并标注"待商务确认" |

### 案例目录匹配（用户给目录时走这条）

1. 先 `ls` 目录，把文件名列出来给用户看一眼，确认是不是这批。
2. 逐个读：docx/pdf 抽正文，表格读单元格，图片（合同首页、验收单、大屏截图）能识别就识别。
3. 按四个字段抽取：**案例名称 / 合作单位（可否实名，看材料里有没有"保密/脱敏"字样）/ 建设内容 / 成效数据**。
4. 抽不全的案例，宁可不写，也不要用"经估算""约"去补数字。
5. 填进案例表，正文的"案例适配性分析"改成针对这几条具体写（哪条可复用、哪条要重新验证）。
6. 目录里没有案例就回到占位状态，并在交付说明里写明"案例目录为空/未提供"。

编制单位默认 **宜春市天码信息有限公司**，编制日期默认 **当天**（脚本自动取系统日期，写成"二〇二六年十一月二日"这种中文格式）。用户没特别说明就不要动这两项。

## 第二步：定结构（六章，按需增删）

```
第一章 项目概述与需求理解     背景 → 需求复述 → 理解与研判 → 总体工作流程（图1）
第二章 总体技术方案          设计原则 → 总体架构（图2）→ 功能模块拆解（每模块一张流程图）
                            → 技术栈汇总表 → 集成与接口 → 安全与运维 → 难点与对策
第三章 相关案例              检索规则 → 案例表 → 适配性分析
第四章 预期效果              原型界面（图）→ 演示视频（只写内容与分镜，文件入附件）→ 视觉设计（图）
第五章 工期与商务条款        阶段计划表 → 甘特图 → 工期顺延/验收标准/质保运维
第六章 结论                  3 段以内：技术可行性 → 选型可替换性 → 扩展性
附件　数字媒体交付清单       视频、原型源文件、设计源文件、案例材料（只列文件与格式，不写路径占位）
```

- **不写运营建议**。全文不出现收费模式、定价、招商、试点推广节奏、人员编制调整；客户的经营目标只在需求复述里转述一句。图内文字同样受约束（`招商触达`→`租户建档`、`服务费调整`→`阈值下发`）。
- **报价默认不写**。用户没明确要金额时，第五章就叫"工期与商务条款"，不出现任何价格、单价、付款比例；用户要报价再补"报价明细表 + 付款节点表"两节。
- **数字媒体（视频、原型源文件、设计稿）一律进附件**：正文只描述"拍什么/画什么"，文件格式、分辨率、交付方式放附件清单，不要在正文里写【文件路径】这类占位。
- 每章另起页；一级标题"一、"、二级"（一）"、三级"1."，不跳级。
- 一个功能模块的标准写法：`1. 建设内容` → `2. 技术栈` → `3. 工作流程（见图N）` → `4. 关键指标`（给数字，不给形容词）。
- 图表编号全文连续：图1…图N、表1…表N，正文先引后出（"见图3""见表5"）。

## 第三步：写 content.py

复制 `scripts/content_template.py`（方案）或 `scripts/content_template_bid.py`（投标）到用户工作目录，按文件头的注释填。

- `META`：标题、副标题、机构、编号、委托单位、`toc_break`。
- `CONTENT`：正文块列表，块类型 `h1/h2/p/lead/fig/tbl/pagebreak`。
- 表格用 dict：`caption/headers/rows/widths/aligns`，**widths 合计必须 = 156**（版心宽度 mm），否则表格会溢出。

细则见 `references/content-blocks.md`。

## 第四步：画图

图片放 `<项目目录>/img/`，文件名与 CONTENT 里一致。三种来源任选：

1. **通用图元**（推荐先试）——`scripts/diagrams.py`：
   ```python
   import sys; sys.path.insert(0, "<技能目录>/scripts")
   from diagrams import vflow, hflow, layers, gantt
   vflow([...], "img/fig03.png", side=["车牌识别","OCR"], loop=(4,1,"异常回流"))
   hflow([{"name":"调研诊断","period":"第 1—3 周","items":["…"]}], "img/fig01.png")
   layers([{"name":"应用层","en":"APPLICATION","color":"#1F5FA8","items":["…"]}], "img/fig02.png")
   gantt([{"name":"…","start":1,"end":3}], "img/fig08.png", milestones=[{"week":3,"label":"方案定稿"}])
   ```
2. **手搓**——`scripts/dkit.py` 提供画布/圆角框/菱形/箭头/虚线/chip，按像素坐标摆位，适合复杂分支。
3. **原型界面**——`scripts/ui.py` 提供浏览器外壳、KPI 卡、折线/柱状图、表格、徽标；按真实界面比例画（1240×800 左右），文字用 18~22px 保证缩到 150mm 宽后仍可读。

硬要求：图内文字最小 8pt 等效；单图高度控制在 120mm 内；**留白要够**，宁可少画一个节点也别让文字压线。投标模式下图不要抢版面——评委看的是条款响应，图只作佐证。

## 第五步：生成与交付

```bash
python <技能目录>/scripts/docbuild.py "<项目目录>/content.py" -o "<项目目录>" -n "<输出文件名>"
```

生成后：

1. 转 PDF（用 office 技能里的 LibreOffice Kit 的 `convert`，或 WPS/Word 另存）。
2. **逐页目检**：封面居中没、目录页码对不对、表格有没有挤行、图有没有断页、页码奇偶是否一右一左。
3. 汇报时用两三句话讲清：文档结构、数据来源（哪些是用户给的、哪些是假设）、还需要用户补什么。
4. 投标模式额外交付《应答核对表》与《废标风险清单》，两份都放正文之外，跟着文档一起发。

## 版式规范（已固化，照抄即可）

| 要素 | 规格 |
|---|---|
| 纸张/边距 | A4；上 37 下 35 左 28 右 26 mm；版心 156×225 mm；每页 22 行 |
| 封面 | 项目名称（二号宋体加粗，行距 35 磅）+ 副标题（三号楷体）+ 编制单位/编制日期（三号仿宋），纵向居中 |
| 章标题 | 黑体二号居中，段前段后各 0.5 行，另起页 |
| 一级标题"一、" | 黑体三号，左空二字 |
| 二级"（一）" | 楷体三号，与正文同段起排，标题后加句号 |
| 三级"1." | 仿宋三号，与正文同段起排 |
| 正文 | 仿宋三号，固定行距 28.8 磅，首行缩进 2 字符，两端对齐，段前段后 0 |
| 图 | 宽 154mm（原型图 150mm），图题黑体小四居中置于图下 |
| 表 | 三线表（顶/底 1.5 磅，表头下线 0.75 磅），表头黑体五号灰底，表内仿宋五号，表题在上，跨页重复表头 |
| 页码 | 宋体四号"— 1 —"，单页居右、双页居左；封面目录不编码，正文从 1 重起 |
| 页眉 | 左上角 LOGO（7.5mm 高）+ 居中文件名（小五宋体）+ 0.5 磅细线；每页都有 |
| 水印 | 每页居中 45° 斜排公司名（`v:shape` + `v:textpath`，浅灰 #D8D8D8、透明度 40%），压在正文之下 |
| 目录 | 收入章与节两级，三号仿宋，点状前导符右对齐页码 |

字体说明：优先 `仿宋_GB2312`／`楷体_GB2312`／`方正小标宋简体`，缺字体时降级为 `仿宋`／`楷体`／`宋体加粗`，字号不变（脚本默认用降级名，兼容性最好）。

## 常见坑（详细原因见 references/ooxml-recipes.md）

- 段落"不缩进"必须显式写 `w:firstLineChars="0"`，只写 `firstLine=0` 会被样式里的 `firstLineChars="200"` 覆盖。
- `pPr`／`tblPr` 子元素有固定顺序，乱序或重复会被渲染器忽略——表格宽度失效、页码不对齐多半是这里。
- 图片段落的行距必须设成单倍，否则固定行距 28.8 磅会把图片裁掉。
- 目录页码用 `PAGEREF` 域（Word/LO 都会在排版时解析），**不要**用 `TOC` 域包一层——LibreOffice 渲染会变灰底且页码全是 1。
- 表格整表加 `keep_with_next` 可避免只掉一行到下一页；但图题千万不要 `keep_with_next`，否则连续多图会被串成一块全推到下一页，留下整页空白。

## 交付前自检

- [ ] 封面：单位与日期正确（日期是当天），LOGO 清晰
- [ ] 目录：页码与正文一致，条目与标题逐字相同
- [ ] 图表：编号连续、正文都有引用、没有孤图孤表
- [ ] 数据：同一数字全文一致；案例/金额若无真实来源已标注
- [ ] 排版：无空页、无半页空白、表格不出血、页码奇偶正确
- [ ] 说明：把"哪些是假设、哪些待用户补"写进汇报
- [ ] 投标模式：★条款逐条确认、应答核对表与废标风险清单已出
