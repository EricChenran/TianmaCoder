# 企业公文生成（official-doc）— 宜春天码信息集团

输入公文要求 → 写一个 `content.json` → 跑一条命令，即产出 **DOCX + PDF** 两个文件。版式已按企业公文标准（GB/T 9704-2012 惯例版）固化在 `scripts/gen_doc.py` 里；PDF 由脚本内置排版引擎直接生成并内嵌中文字体，**不依赖 Word/WPS/LibreOffice**。

## 路径与运行约定

- 技能目录是**只读资源**：不要在技能目录里写任何文件。
- 相对路径（如 `scripts/gen_doc.py`）都相对技能目录解析，调用脚本时用技能目录的绝对路径。
- 临时 `content.json` 与生成物一律放在**用户的工作目录**：`content.json` 用后删除，成品留在工作目录里，这样 `present` 能把它们直接呈现给用户。
- 用 PATH 上的 `python` 运行脚本；脚本需要 `python-docx`、`reportlab`、`Pillow`。若 PDF 步骤报缺 `reportlab`，**此时 DOCX 已经生成**：交付 DOCX 并说明 PDF 需要该依赖，不要静默跳过 PDF。

## 固化版式（不要手工调整）

| 要素 | 规格 |
|---|---|
| 纸张/页边距 | A4；上37 下35 左28 右26mm（版心156×225mm） |
| 页眉 | 每页左上角集团LOGO（透明底、绿色标识），不占正文 |
| 红头 | "宜春天码信息集团文件" 红色 小初36磅 小标宋（无则宋体加粗） 居中 |
| 文号 | 三号仿宋 黑色 居中；上行文时居左并右侧同行排"签发人：×××" |
| 分隔线 | 文号下 1.5磅红色横线 |
| 标题 | 二号 小标宋（无则宋体加粗） 黑色 居中 |
| 正文 | 三号仿宋，行距固定28磅（落款/版记收尾需要时自动微调至25~27磅），首行缩进2字符，两端对齐 |
| 标题层级 | 一、→三号黑体；（一）→三号楷体；1.→三号仿宋加粗 |
| 落款 | 署名与成文日期自动水平居中对齐，日期右空四字；脚本保证落款不孤悬页首 |
| 版记 | 抄送/印发单位 四号仿宋带细横线，固定在末页版心下缘 |
| 页码 | 四号宋体"— N —"，单页码居右、双页码居左（奇偶页页脚） |
| 字体择优 | 方正小标宋_GBK>简体>华文中宋>宋体；仿宋_GB2312>仿宋；楷体_GB2312>楷体（运行时自动检测本机已装字体，DOCX/PDF 一致） |

## 执行流程（严格按序，一次完成）

1. **起草全文**（唯一需要思考的步骤）：按文种规范写正文，层级编号用 一、→（一）→1.→（1）。文号一律用六角括号〔〕。用户没给文号则留空（脚本自动生成"天码发〔年〕　号"占位）并在汇报时提醒补填；日期没给用今天；引用其他文号也用〔〕。
2. **写 `content.json`**（UTF-8，放工作目录）：按下方 schema 一次写完。
3. **生成**：`python <技能目录>/scripts/gen_doc.py <content.json 的路径> -o <用户工作目录>`。**必须给 `-o`**——缺省会输出到桌面，成品就不在工作目录里了；一步出同名 `.docx` + `.pdf`。
4. 删除临时 `content.json`，用两三句话汇报（文种、标题、文号、输出位置），并调用 `present` 把 `.docx` 与 `.pdf` 呈现给用户。
5. 生成后不要打开文档自查：分页、落款防孤页、版记沉底由脚本自动处理（行距 28→25 磅逐级试探）。

## 效率红线

- 不调用 office-docx / office-pptx / office-xlsx 技能，也不读它们的参考资料——版式已内置。
- 不向用户确认大纲或方案，直接产出；只有事由完全缺失时才询问。
- 报错时按脚本提示修 JSON 重跑即可，不要改脚本、不要改版式。
- 用户没提的要素（密级、紧急程度、签发人、抄送、附件）一律省略，不要画蛇添足。

## content.json schema

```json
{
  "letterhead": "宜春天码信息集团文件",
  "logo": true,
  "secret": "",
  "urgency": "",
  "signer": "",
  "doc_number": "天码发〔2026〕18号",
  "title": "关于……的通知",
  "recipient": "集团各部门、各分（子）公司：",
  "body": [
    {"t": "p",  "x": "正文段落……"},
    {"t": "h1", "x": "一、……"},
    {"t": "h2", "x": "（一）……"},
    {"t": "h3", "x": "1.……。"},
    {"t": "att_head", "x": "附件1"},
    {"t": "page"}
  ],
  "attachments": ["附件名称1"],
  "signature": "宜春天码信息集团",
  "date": "2026年9月12日",
  "cc": "集团领导，财务部。",
  "issuer": "宜春天码信息集团综合管理部"
}
```

- `letterhead` 省略默认"宜春天码信息集团文件"；部门发文改"宜春天码信息集团××部文件"。
- `logo` 省略为 true（页眉LOGO）。`secret`/`urgency`/`signer`/`attachments`/`signature`/`cc`/`issuer` 不需要就省略。
- `body` 的 `t`：`p` 正文段、`h1/h2/h3` 三级标题、`att_head` 附件首页顶格标识（配 `page` 分页使用）、`page` 分页。
- `doc_number` 缺省自动生成"天码发〔当年〕　号"占位；上行文（请示）用"天码请〔年〕×号"并必填 `signer`。

## 常用文种要点（起草时参照）

- **通知/印发型**：缘由 →"现将……印发给你们，请结合实际认真贯彻执行"→ 执行要求 → 施行与解释条款。
- **请示**：一文一事；结尾"妥否，请批示。"；必填 `signer`，文号用"天码请〔年〕×号"。
- **报告**：不夹带请示事项；结尾"特此报告。"
- **批复**：引述来文（标题+文号）→ 表态（同意/不同意）→ 要求。
- **函**：平行文，用语平和；结尾"盼复。"或"特此函达。"
- **纪要**：可无 `recipient`，直接综述（"会议听取了……会议认为……会议决定……"）。
