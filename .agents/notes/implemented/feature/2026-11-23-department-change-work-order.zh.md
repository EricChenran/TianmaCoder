# Agent Note: 工单闭环——商务部出单、技术部处置

Status: implemented

[English](2026-11-23-department-change-work-order.md) | 中文

## Problem

商务部的日常输入是文字与截图混在一起的客户需求。当时这个模式已经能出需求文档、报价单和案例清单，却没有办法把这类输入整理成一张可派工的表，也没有任何随包脚本能写出内嵌图片的 Excel。手工重建这张表，等于把模板本来要省下的那轮复核又做一遍。

## Decision

[部门模式的机制](2026-09-23-department-modes.zh.md)没有变化：仍然是一条字面系统提示词节加一个发布出来的工具箱。本条只记录在它之上新增的能力——`assets/business/gen_workorder.py` 加入工具箱，规则增加一节 `# 改动任务工单`。脚本读一份 `content.json`、写一个 xlsx；模型只负责读懂客户材料、拆成任务行、把输入填好。

- **六列固定，顺序按业务要求排**：时间、任务明细、当前现象、期望改动后、证明截图、状态。一行就是一件能独立验收的改动。不加序号列、优先级列或排期列——这张表是对客的需求登记，不是进度看板。
- **截图只从磁盘文件嵌入**。用户贴在对话里的图，其附件标识不是模型可以命名的路径，因此规则要求用户把截图另存为文件（建议放在 `<客户名>/images/`），拿不到文件时改用 `proof` 说明。每条图片路径依次按原样、按 JSON 所在目录、按当前目录解析；任一路径找不到就带行号中止生成，而不是产出一张悄悄少了证据的表。
- **校验一次报出全部问题**。必填 `project`，以及每行的 `task`、`phenomenon`、`expected`。状态口径封闭为待处理、处理中、已完成、已验收、已驳回、已取消，缺省待处理，因此客户刚提出的需求不会被记成已完成。`blank_rows` 满足"只要空模板"的请求，但不放松行校验。
- **版式固化在脚本里**：标题行与信息行合并居中、表头冻结且随页重复并带筛选、单元格自动换行加细边框且行高随图自动调整、状态按口径着色、表尾说明行、A4 横向按页宽缩放、页脚页码。
- **只出 xlsx**。`to_pdf.py` 通过 COM 驱动 Word，因此规则要求如实说明无法承诺 PDF，而不是再加一条转档通道。

模式在预设卡片与使用指南（双语）里都列出了这项能力，因此网页端该行卡片的 e2e 期望快照随之更新。

### 技术部那半边

同一张工单驱动另一端。`assets/tech/read_workorder.py` 把工单读成 JSON，`build_disposition.py` 写出处置表，并对着那张工单核对行：缺项、重复、越界、图片找不到都会带行号中止生成——「每项需求都要对上」由脚本强制执行，而不是靠规则里的一句承诺。每行的「证明截图」单元格里放脚本合成的改前/改后对比图（标签、说明行、环境行都按面板宽度换行），确实没有界面可截的改动就在单元格里写明原因，而不是留一张空截图。

技术部那一行现在通过和商务部相同的安装路径发布自己的工具箱（`department/tech-tools`），于是两个部门都以 `DSH_DEPARTMENT_TOOLS` 拿到各自脚本，不必新增技能条目。派并行子 Agent 之前先问用户是规则的一部分，共享端口、构建产物、浏览器用户目录与数据库的任务仍然串行。

## Testing

`tests/department-prompts.spec.ts` 钉住了六列契约、工具箱命令、只认磁盘截图这一条、封闭的状态口径，以及生成脚本自身的表头字面量。生成脚本用一份三行样例实跑过——两张竖排截图、一张超高截图、一条缺图说明——并经随包 LibreOffice 渲染做版式目检；图片缺失与必填字段缺失两种情况都以非零退出并点名出错的行。

## Alternatives considered

**做成技能而不是工具箱脚本。** 这个模式现有的文档产出——需求文档、报价单、水印、PDF——都是 `DSH_DEPARTMENT_TOOLS` 背后的脚本，工单是同一形态的活：一个输入文件进、一个文件出。做成技能会给每次商务部请求多一条目录项，并且让模板变成会话去读的文档，而不是去跑的命令。

**并进 `gen_quote.py` 或 `gen_doc.py`。** 那两个脚本拥有带固定水印、页眉页脚与合计校验的 Word 版式；带图的电子表格不共享其中任何机器，合并只会把一份脚本的失败模式变成另一份的。

**直接接收对话里粘贴的截图。** 附件存储是内容寻址的，没有模型可见的路径，生成脚本打不开；让脚本去翻存储既把工具箱绑到 harness 内部，也仍然让模型猜哪个对象属于哪一行。让用户落盘一个文件，表才站得住。

**缺图就留空列而不中止。** 一列空白的证据看起来像"不需要截图"，而不是"证据缺失"——正是「证明截图」这一列要防的误读。

**给技术部也做成一个随包技能。** 技能正文按需加载、却给每次技术部请求都加一条目录项；这条闭环是一节提示词加一次渲染，契约在规则里已经写全，而工具箱的安装路径本来就在为部门脚本服务。

## Consequences

- 商务部模式多出约 700 token 的提示词（合计约 4,200，每请求一次），工具箱多发布一个脚本；未选择的模式仍然零开销。
- 技术部多出约 620 token 的提示词（合计约 7,400）与两个发布到独立工具箱目录的处置脚本。
- 工单与处置表都需要带 `openpyxl` 与 `Pillow` 的解释器；缺任一依赖时脚本打印安装命令后退出，不会产出半张表。该限制记在包 README 里。
- 客户需求从此有一张固定、可复核的登记表，且模式不会代客户把需求标成已完成。
- 处置表只要缺项、重复或越界就中止生成，于是「每项都覆盖」不再是承诺，而是前置条件。
- 只出 Excel 是明确的：要 PDF 需要这条工具箱没有的转换通道。
