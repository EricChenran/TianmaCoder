# Agent Note: 侧栏里的 OA 工作台

Status: implemented

[English](2026-11-23-oa-workbench-panel.md) | 中文

## 问题

本产品对天码 OA 的接入停在账户这一层：验证码登录对话框、侧栏启动器，以及展示资料与计数的设置区块。员工每天真正在做的事——看站内消息、处理审批、记待办、查今日日程与任务、打卡——仍然要离开产品去 OA 应用或小程序。Host 早就持有了 Token，后端也早就提供了这些读取，缺的只是一个界面和它背后的操作。

## 决策

- **一个一级面板，七个模块。** `main` 槽以 `oa-workbench` 为 key 注册面板，页签是概览、消息、审批、待办、日程、任务、考勤；同时在 `sidebar.panellist` 以 order `-10` 占一行，入口排在现有面板之前。
- **二级页签常驻不销毁。** 消息或审批在列表旁开页签；模块与已打开的单据只隐藏、不卸载，因此筛选、滚动位置和写到一半的审批意见在切换后都还在；关闭单据只销毁那一份。
- **所有读取都走 Host。** 账户服务新增 23 个 Remote 方法，覆盖消息及其已读状态、通知开关、待办、审批（列表、详情、动作、类目、提交、草稿）、今日日程、任务看板与完成、考勤。它们复用 `authorized()`，过期 Token 只静默续签一次，浏览器始终拿不到 Token。
- **线上词汇在边界处收口。** 九类消息按后端 `system` 映射，未知落 `other`；审批与节点状态未知落 `unknown` 而不是整表失败；数字型实发金额转文本。审批派生的休假条目保留复合字符串 id 并标记为 `kind: 'leave'`，今日日程不会把同事的休假当成会议。
- **一处后端无法替我们表达的校验。** 空意见的驳回在模块内就被拦下，不发请求；其余拒绝一律显示后端原话，包括重复点击时的"无审批权限或已审批"。
- **按片读取，而不是一坨。** 工作台快照分成五片——计数、消息、待办、考勤、通知开关——某一片被拒只在该模块内报错，每次写操作只重载受影响的那一片。
- **不读打卡记录。** `GET /attendance/records` 会把历史上只有上班卡的日期改写成早退，所以面板只提供今日状态与月度汇总，把记录改写留给后端自己的界面。

## 测试

账户包的用例钉住新的线上契约：消息类型与 payload 投影及 `other` 回退、已读路由、偏好键、待办路由（含 `DELETE`）、审批投影与拒绝文案、类目映射、提交与草稿的请求体差异、日程中会议与休假派生项的区分、任务看板与完成路由、打卡的布尔午休字段、以及月度汇总里以文本承载的罚款。客户端用例渲染审批模块（空意见驳回被拦、通过时带上已填意见）、日程与任务模块，以及面板本身——七个模块页签，打开未读消息会标为已读并在列表旁开页。

本次跑过的门禁：包级与仓库级类型检查、`oxlint`、`verify-client-ui-i18n`、中英配对、客户端 slot 目录，以及通过纯净性检查的客户端 bundle 构建。

## 备选方案

**把工作台放进设置区块。** 设置是从账户菜单进入的配置界面；每天要看的工作清单放在那里会深两层，而且仍在一个以一次性编辑为主的页面里。

**把工作台做成独立插件包。** 它与现有界面共享账户快照、登录对话框和 locale 命名空间。拆包就得跨插件边界去"打开登录对话框"，这是客户端规则禁止的，或者把那份状态复制一遍。

**用左侧列表加右侧详情分栏，而不是页签。** 产品在面板内已有二级页签的用法，沿用它只保留一套导航模型；分栏还会在笔记本上压缩列表列宽。

**在浏览器里直接调 OA 后端。** 后端只放行自己的 CORS 来源，Token 也会落进浏览器存储。把调用留在 Host，凭据留在 seam 里，浏览器只面对一个 BFF。

**顺带暴露打卡记录列表。** 那个读会改历史，从工作台页签里看一次就等于改了用户当月的考勤。

## 影响

- 侧栏多了一个入口，因此抓取侧栏的组装态 Web 快照在面板落地时需要重录。
- 审批一次只处理一份单据：员工端既没有批量动作也没有转交，模块不自行发明。
- 工资条与文件云传在 Host 提供读取之前不进入工作台；宣布它们的消息仍可打开自己的 payload。
